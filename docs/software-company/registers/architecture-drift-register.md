# Architecture Drift Register

Architecture drift means the implementation no longer matches the intended architecture or creates a future scaling, quality, security, billing, or maintainability problem.

| ID | Area | Planned Direction | Actual State | Risk | Required Fix | Owner | Target Date | Status |
|---|---|---|---|---|---|---|---|---|
| ADRIFT-M1-001 | Suite Memory | Suite Memory is a structured system of record accessed through a shared context builder | `Suite.brand`, `Suite.strategy`, and regeneration feedback are read/written directly by multiple services with no versioned contract | User edits can be overwritten or ignored; generation modes can diverge | Define Suite Memory v0 keys, merge rules, and shared generation context builder/normalizer | Developers Manager + Architecture | M1 before generation changes | open |
| ADRIFT-M1-002 | Generation workflow | Generation runs as durable jobs/workers with retry, timeout, and provider capacity handling | `GenerationJob` is persisted, but execution uses process-local FastAPI background tasks | Deploys/restarts/provider delays can leave jobs stuck or lost | Add timeout/stuck handling and decide whether M1 requires a real worker queue | Developers Manager + DevOps + Architecture | M1 release candidate | open |
| ADRIFT-M1-003 | Media artifacts | Generated assets store public URL, backend, content type, dimensions, status, source, and suite linkage | `ContentPost.media_urls` is only a URL list; media failures can still create pending posts with empty media | Broken or local-only media can appear as blank review cards or unsafe publish attempts | Add media readiness/error/backend metadata to content responses and block/explain non-public publish media | Developers Manager + DevOps | M1 release candidate | open |
| ADRIFT-M1-004 | Publishing | Publishing is a separate workflow with durable per-platform result state | Request lifecycle publish can mark a post `published` when only one requested platform succeeds | Partial failures can be hidden from users | Persist per-platform success/error and represent partial publish separately from full publish | Developers Manager | M1 release candidate | open |
| ADRIFT-M1-005 | Connections and analytics | Integration status separates auth, selected account, publishing, analytics, ads read/write readiness, and missing permissions | Readiness is inferred from `Suite.connections`; analytics/campaign APIs return mixed errors/warnings | Users can see misleading all-zero or ambiguous dashboards | Return typed capability/data-quality states for connections, analytics, and campaign reads | Developers Manager + DevOps | M1 release candidate | open |
