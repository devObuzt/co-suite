UX Style Intake

تم تثبيت قاعدة جديدة: تجربة الاستخدام نفسها لازم تكون قرار واضح قبل التصميم والكود.

الخلاصة

لا يكفي أن نسأل عن البراند والألوان؛ لازم نسأل العميل أو صاحب المشروع: كيف بدك التطبيق يحس للمستخدم؟

القرار

أي مشروع جديد فيه واجهة، تطبيق، لوحة تحكم، أو استخدام طويل داخل النظام، لازم يمر بمرحلة UX Style Intake.

  • هادئ ومركز.
  • حيوي ولعوب.
  • فاخر وتحريري.
  • عملي وكثيف للمستخدمين المتكررين.

اتجاه OneShare الافتراضي

  • مريح للعمل لفترات طويلة.
  • عصري وجذاب بدون إزعاج بصري.
  • واضح وقوي في عرض الشيء الذي يعمل عليه المستخدم الآن.
  • يستخدم animation خفيف فقط عندما يخدم الفهم أو التقدم أو التأكيد.
  • لا يستخدم حركة مستمرة أو مؤثرات تشتت المستخدم.
  • يعرض المهم الآن، ويخفي التفاصيل المتقدمة حتى يحتاجها المستخدم.

مساهمة الأقسام

Product - Omar Nassar

يسأل العميل عن إحساس الـ UX المطلوب، أو يقترح اتجاهات ويسجل القرار ومدة الجلسات المتوقعة.

Design - Noa Barak

تترجم القرار إلى وضوح، hierarchy، progressive disclosure، حركة خفيفة، ودعم RTL/LTR.

QA - Lina Saad

تفحص الراحة، قابلية القراءة، حالات الانتظار، والحركة خلال جلسات استخدام أطول.
