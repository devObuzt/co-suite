التاريخ: 2026-06-08 01:35
المسؤولون: Samer Nassar / Developers Manager، Noor Barakat / QA Manager

ماذا أنجزنا

  • فحصنا كرت Recent Content وأفعال المستخدم عليه.
  • أضفنا feedback واضح داخل الكرت بعد حفظ التعديل، نسخ الكابشن، الجدولة، النشر، تحديد المحتوى كمستخدم خارج التطبيق، ورفض المحتوى.
  • أضفنا معالجة أخطاء مرئية لهذه العمليات حتى لا يفشل الزر بصمت.
  • عدلنا منطق reject حتى لا يغلق صندوق سبب الرفض إذا فشلت العملية.

لماذا هذا مهم

الكرت هو مكان العمل اليومي للمستخدم. المستخدم يراجع، يوافق، يرفض، يعدل، ينسخ، يجدول، وينشر من هنا. أي عملية صامتة أو غير مفهومة تخلق إحساس أن التطبيق غير ثابت. الرسائل الصغيرة هنا ترفع الثقة بالتجربة.

التحقق

  • تم تشغيل npm run build بنجاح.
  • لا يوجد كسر TypeScript أو Next build بعد التعديل.

الخطوة المقترحة التالية

  • فحص حالة media preview للفيديو والصور، خصوصاً عندما يكون الرابط محلي أو R2 غير جاهز.
  • بعدها فحص Product Bulk Studio flow لأنه ما زال من أهم المنتجات العملية داخل التطبيق.
